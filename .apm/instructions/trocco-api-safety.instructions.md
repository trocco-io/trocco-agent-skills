# TROCCO API 利用時の必須ルール

## 1. API は必ずラッパー経由で呼ぶ

TROCCO API を叩くときは、**ラッパー `trocco-api.sh` 経由**で呼ぶこと。`curl` で直接叩かない。
ラッパーは各スキルに同梱されている。実行するスキルの `SKILL.md`「大原則」の手順でパスを確定して使う。

```bash
bash <ラッパーのパス> /job_definitions?limit=200
bash <ラッパーのパス> /teams/1
```

- ベース URL と `Authorization` ヘッダーはラッパーが所有する。**パス以降と curl 引数だけ**を渡す。
- ラッパーが API キーを解決するため、**キーの値を読む必要はない**。

## 2. API キーの値を露出させない

- キー値を `echo` / `printf` で**出力しない**。ファイルやコミットに**残さない**。
- `env` / `printenv` / `declare -p` などで**環境変数をダンプしない**。
- `curl` の `-v` / `--verbose` / `--trace` を**使わない**（Authorization ヘッダーがログに出る）。
- エラーを報告するときも、キーの値そのものを引用しない。

これらは PreToolUse hook でも機械的に block されるが、hook は失敗時に素通りすることがある。
block されなかったことを許可の根拠にせず、規約そのものを守ること。

## 3. 読み取りは自由・変更は必ず承認を得る

- **読み取り**（GET・一覧・検出・診断）は自由に実行してよい。
- **変更系**（PATCH / POST / DELETE、リネーム、設定変更、削除）は、
  **対象一覧と before/after を提示してユーザーの承認を得てから**実行する。
- 承認後も、**まず少数で試して結果を確認**してから横展開する。
- 再実行しても二重適用にならないよう、適用前に「すでに設定済みか」を判定する。
